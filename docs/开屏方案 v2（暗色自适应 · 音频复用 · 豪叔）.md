## 1. 主题系统设计（新增）

### 1.1 一个比「跟随系统」更好的信号源：Claude 自己的主题偏好

勘测发现 Claude Desktop 的配置文件里记录着它自己的外观设置：

```
~/Library/Application Support/Claude-3p/config.json   ← 当前 3P 模式
~/Library/Application Support/Claude/config.json      ← 1P 模式
```

关键键（已实测存在，本机当前值均为 `system`）：

```json
"userThemeMode": "system"   // 取值应为 "system" | "light" | "dark"
```

这意味着开屏可以做成**和 Claude 界面永远同主题**，而不只是跟随 macOS：用户把 Claude 单独设成 Dark 时，开屏也是 Dark；设为 System 时才去看系统外观。

**解析优先级（启动器在拉起 Claude 之前算好）：**

```
1. 读 Claude 配置的 userThemeMode
   - "dark"  → dark
   - "light" → light
   - "system" / 缺失 / 读不到配置 → 进入第 2 步
2. 读 macOS 系统外观
   - NSApp.effectiveAppearance.bestMatch(from: [.darkAqua, .aqua]) == .darkAqua → dark
   - 否则 → light
3. 用户在启动器 config.json 里显式写了 themeOverride: "light"|"dark" → 最优先，覆盖以上一切
4. 一律解析为明确的 "light" 或 "dark"，注入 window.__DSH_STARTUP__.theme
```

**配置选哪个文件**：两个都存在时取 `config.json` **mtime 更新**的那个（本机 `Claude-3p` 是今天在用的，`Claude` 停在 10 月）。读不到就回退系统外观。**只读 `userThemeMode` 一个键，不落盘、不记录其余内容。**

为什么不让页面自己做 `theme: 'auto'`：引擎只认 `C.theme === 'dark'`（`splash.js:562`），传 `auto` 等于 light（源码没有 `matchMedia` 分支）。所以必须在注入配置前由启动器解析成具体值——这也是不需要 fork 引擎的地方。

**中途切换系统主题**：v1 不处理（开屏只播 10 秒左右，会话内切换极罕见）。P2 可监听 `AppleInterfaceThemeChangedNotification` 后对 `root.classList.toggle('dsu-dark', …)` 做热切换。

### 1.2 暗色主题现状：引擎已有一半，缺 4 个口子

引擎本身带完整的 dark 主题（`splash.css:91-103` 的 token 覆写，另有 `.dsu-plate` / `.dsu-wm` / `.dsu-vignette` / `.dsu-scanline` / glass 五处暗色适配，`splash.css:130,148,726,1003,1128`）。暗色不是「新做」，是「补完」。

**必须补的 4 个缺口**（都是原版暗色主题里就存在的问题）：

| # | 位置 | 现状 | 问题 | 修改 |
|---|---|---|---|---|
| 1 | `.dsu-wash`（`splash.css:256-263`） | 背景写死 `#8b8a88` 中灰 | 暗色下从纯黑瞬间跳到中灰再落回近黑底板，亮度过曝，刺眼 | 新增 `#dsh-startup-root.dsu-dark .dsu-wash { background: #2a2724; }`（暖深灰，保留「光洗」节奏但不刺眼） |
| 2 | 终幕闪白（`splash.js:1659`） | `opacity = 0.72` 写死 | 暗色下 72% 白闪像闪光弹 | fork 一行：`0.72` → 暗色 `0.32`（可用 `C.theme === 'dark' ? 0.32 : 0.72`） |
| 3 | 色散故障混合模式（`splash.css:657-671`） | 文字层 `multiply`、黑框层 `screen` | dark 下欢迎文字是浅字铺深底，`multiply` 会把红蓝副本压成黑、故障看不见；而 dark 的黑框变成了浅底，`screen` 又太弱 | 暗色下对调：`#dsh-startup-root.dsu-dark .dsu-glitch[data-text]::before/::after { mix-blend-mode: screen; }`、`#dsh-startup-root.dsu-dark .dsu-glitch.dsu-glitch-box::before/::after { mix-blend-mode: multiply; }`（需视觉实测确认） |
| 4 | 光晕高光蓝（`splash.css:798,802`） | `rgba(41,113,184,…)` 写死 | 换 Claude 后应是低饱和蓝 `#6a9bcc` 同族 | 改为 `rgba(106,155,204,0.55)` / `0.45`（两处），亮暗通用 |

另有一处**不属于暗色、但换皮必须改**：`.dsu-pulse` 里的硬编码橙 `rgba(255,117,0,…)`（`splash.css:559-560`）→ coral。

### 1.4 暗色下的时序（与亮色唯一不同：洗白那 260ms）

| 区间 | 亮色 | 暗色 |
|---|---|---|
| 黑幕 → 标识 | 纯黑 + 白字 | 完全相同（黑幕天生暗色友好） |
| 过场洗白 | 220ms 升到中灰 `#8b8a88` → 底板淡入 → 720ms 洗白退场 | 220ms 升到暖深灰 `#2a2724` → 暗底板淡入 → 720ms 退场；整体光感是「暗房亮起」而非「过曝」 |
| 第二幕–第五步 | 暖白档案底板 | 暖黑档案底板，文字/线条/准星按 token 反转 |
| 终幕闪白 | 72% 白闪 | 32% 暖白闪（保留「一击」的节奏，不刺眼） |
| 揭幕 handoff | 放大 + 失焦 + 淡出露出 Claude | 相同；且因为开屏和 Claude 同为暗色，衔接更无缝 |

### 1.5 启动器侧实现要点（Swift，示意）

```swift
func resolveTheme() -> String {
    if let forced = userOverrideTheme { return forced }          // config.json: themeOverride
    if let mode = readClaudeUserThemeMode() {                     // 只读 userThemeMode 一个键
        if mode == "dark" { return "dark" }
        if mode == "light" { return "light" }
    }
    let dark = NSApp.effectiveAppearance
        .bestMatch(from: [.darkAqua, .aqua]) == .darkAqua         // "system" 或读不到时
    return dark ? "dark" : "light"
}

func readClaudeUserThemeMode() -> String? {
    let candidates = [
        "~/Library/Application Support/Claude-3p/config.json",
        "~/Library/Application Support/Claude/config.json"
    ].map { ($0 as NSString).expandingTildeInPath }
        .filter { FileManager.default.fileExists(atPath: $0) }
        .sorted { mtime($0) > mtime($1) }
    guard let path = candidates.first,
          let data = FileManager.default.contents(atPath: path),
          let obj = try? JSONSerialization.jsonObject(with: data) as? [String: Any]
    else { return nil }
    return obj["userThemeMode"] as? String
}
```

解析结果通过注入脚本写进配置：`theme: "dark"` 或 `"light"`；其余 38 个字段照评估文档。

## 2. 音频复用方案（个人自用）

### 2.1 结论：一步都不用重新做音频

- 8 个 mp3（`line-1..6` + `sfx-tick` + `sfx-ticks-run`，共 254 KB）**原样打包**进启动器 `Resources/assets/`。
- 配置保持引擎默认：`voiceSource: 'asset'`、`sfx: 'audio'`、`voice: true`、`sound: true`。
- 评估文档里的 P2「自产音频」阶段取消，整个工期少半天。
- 版权说明一句话：个人本机自用没有问题；**不要把打包了这些素材的 app 发给别人**（素材来自第三方视频与克隆音色，不在代码的 MIT 许可内）。

### 2.2 读取方式不变：v1 用 base64 内联

`file://` 下 `fetch()` 不可用（`splash.js:1050,1066` 用的是 fetch），所以照旧 fork 一个 `assetUrl()` + 构建期把 8 个 mp3 转成 base64 表（`window.__CLAUDE_SPLASH_AUDIO__`），`atob → ArrayBuffer → decodeAudioData`。体积 254 KB → 约 340 KB，无感。

（P2 可选优化：`WKURLSchemeHandler` 省掉 base64 膨胀，注意 MIME 必须按扩展名映射——评估文档 §6 的 P0 项。）

### 2.3 第一句语音的已知限制（原版就存在，不是本次引入）

浏览器/WKWebView 的自动播放策略：用户第一次点击之前，AudioContext 可能处于 suspended。DSH 的 README 自己写明「声音只能由用户点击后开始」。于是**第 1 步的 line-1 很可能等到你点「授予访问权限」时才出声**，或者干脆静音过去。

三个选项：

| 选项 | 效果 | 建议 |
|---|---|---|
| A. 保持原样 | 与 DSH 完全一致的体验；第一句常静音 | 默认 |
| B. 点击优先 | fork 一处时序：第 1 步的 `voice.line(...)` 挪到 `waitAction()` 之后 | 如果你在意「开场必须有声」 |
| C. 静音版 | `voice:false`，只留音效 | 想安静时用 |

`WKWebViewConfiguration.mediaTypesRequiringUserActionForPlayback = []` 只对 `<audio>` 元素生效，对 Web Audio 不一定——T12 PoC 里顺便验证 `AudioContext state`。

## 3. 身份定制：豪叔

### 3.1 一个必须显式设置的坑：纯中文名 → `OPERATOR`

引擎的规范化逻辑（`splash.js:201-204`）：

```js
out.identity = String(out.identity || DEFAULTS.identity).slice(0, 48)
out.identityId = String(out.identityId || out.identity)
  .toUpperCase().replace(/[^A-Z0-9]/g, '').slice(0, 12)
if (!out.identityId) out.identityId = 'OPERATOR'
```

注释写得很明白：「代号取身份名称里的字母数字；纯中文名字取不到时退回 OPERATOR」。

- `identity: '豪叔'` 没问题（欢迎语、身份卡正常显示）。
- 但若**不填 `identityId`**，它从 `豪叔` 里取字母数字 → 空 → 回退成 `OPERATOR`。所以 `identityId` 必须显式给值。

### 3.2 推荐取值

| 字段 | 值 | 显示效果 |
|---|---|---|
| `identity` | `豪叔` | 终幕「欢迎 豪叔 开始对话」；身份卡「用户名称 豪叔」 |
| `identityId` | `0087`（推荐，简洁）或 `HS-0087`（显示为 `HS0087`，连字符会被去掉） | 右下「· IDENTITY CONFIRMED : 0087」 |
| `accessLevel` | `PRO`（或 `MAX`） | 身份卡「访问等级 PRO」 |

### 3.3 文案落点（与评估文档 §4.1/4.2 合并后的最终值）

- 终幕欢迎模板（`splash.js:748`）：`'欢迎 ' + C.identity + ' 开始对话'` → 「欢迎 豪叔 开始对话」
- 右下读数（`splash.js:749`）：`'· IDENTITY CONFIRMED : ' + C.identityId`
- 身份卡三行（`splash.js:1585-1595`）：用户名称 / 会话编号 / 访问等级
- 黑幕组织名改为 `CLAUDE / ANTHROPIC / CLAUDE DESKTOP`（不含中文「克劳德」）；品牌块只保留 `CLAUDE / ANTHROPIC` 两行（去掉 `DESKTOP APP` 行）——按用户要求调整；页脚 `POWERED BY ANTHROPIC`——与身份名无关，保持品牌文案。

## 4. 更新后的启动流程（含主题解析）

```
点击 ClauEd 图标
  ├─ Claude 已在运行？ → 只激活 Claude，退出（不播开屏）
  ├─ 读启动器 config.json（enabled / themeOverride / speed / preset / hybrid…）
  ├─ resolveTheme():  Claude config userThemeMode → 系统外观 → 得到 "light"|"dark"
  ├─ t=0   全屏黑窗显示（窗口背景 #000，两个主题一致）
  ├─ 加载壳页面：critical CSS → 挂载点 → 完整配置（theme=已解析值）→ base64 音频表 → splash.js
  ├─ t≈1.6s  open -b com.anthropic.claudefordesktop（不带调试参数）
  ├─ 六幕播放（暗色走 §1.4 的暗色时序）
  ├─ 终幕 → handoff（透明揭幕优先，失败回退整窗淡出）
  └─ 收窗、terminate；任何异常只关自己的窗口
```

配置示例（启动器自己的 `config.json`，不是 Claude 的）：

```json
{
  "enabled": true,
  "themeOverride": "auto",
  "preset": "claude-warm",
  "darkWash": "soft",
  "speed": 1.0,
  "requireInteraction": true,
  "voice": true,
  "sound": true,
  "voiceFirstLineAfterClick": false,
  "identity": "豪叔",
  "identityId": "0087",
  "accessLevel": "PRO"
}
```

`themeOverride: "auto"` 即 §1.1 的解析链；写 `"light"`/`"dark"` 则强制。

## 7. 需要你拍板的选择
